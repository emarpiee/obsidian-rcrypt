[Obsidian](https://obsidian.md) 向けのクライアントサイドファイル・フォルダ暗号化プラグインで、公式の [Rclone Crypt](https://rclone.org/crypt/) 標準と完全に互換します。

`obsidian-rcrypt` は、純粋な Web 暗号化プリミティブ（`@noble/ciphers` および `@noble/hashes`）を使用して 100% オフラインで動作します。ローカルの `rclone` バイナリのインストールは不要で、デスクトップおよびモバイルプラットフォーム（Android、iOS、macOS、Windows、Linux）でシームレスに動作します。

> **免責事項**: 本プラグインは独立したオープンソースプロジェクトであり、公式の [Rclone](https://rclone.org) プロジェクトとは関係がなく、提携・維持・承認されているものではありません。

---

## 主な機能

- **Rclone との 1:1 相互運用性**：Obsidian でファイルを暗号化し、公式の Rclone CLI（`rclone cat`、`rclone mount`、`rclone copy`）で直接復号またはマウントできます。
- **Crypt プロファイル管理**：カスタムパスフレーズ、ソルト、ファイル名暗号化モード、エンコーディングを持つ複数の暗号化プロファイルを設定できます。
- **コンテキストメニュー・パレット統合**：ノート、添付ファイル、またはフォルダ全体を右クリックして暗号化または復号します。コマンドはアクティブなプロファイルに基づいて動的に更新されます。
- **柔軟なファイル名モード**：**標準**（AES-256-EME）、**難読化**（Rclone 文字ローテーション）、**オフ**（オプションの拡張子サフィックス付きの平文ファイル名）の 3 つのモードをサポートします。
- **ネスト（多層）暗号化**：異なるまたは同一のプロファイルを使用して、すでに暗号化されたファイルを再帰的に暗号化します。復号時に内部の暗号化レイヤーが残っていることをスマートなペイロードバイト検査で通知します。
- **RAM 専用セキュリティと i18n**：デフォルトで認証情報を揮発性メモリ（RAM）のみに保持します。11 言語に完全ローカライズされ、RTL の自動サポートを備えています。

## インストール

### オプション 1: Obsidian 公式コミュニティプラグインストア
1. Obsidian の**設定** $\rightarrow$ **コミュニティプラグイン**を開きます。
2. **ブラウズ**をクリックし、**RCrypt** を検索します。
3. **インストール**をクリックし、**有効化**をクリックします。

### オプション 2: BRAT 経由（プレリリース / ベータテストに推奨）
1. Obsidian に [BRAT](https://github.com/TfTHacker/obsidian-42-brat) をインストールします（**設定** $\rightarrow$ **コミュニティプラグイン** $\rightarrow$ **BRAT** を検索）。
2. BRAT の設定を開き、**Beta プラグインを追加**をクリックします。
3. リポジトリ URL を入力します：`https://github.com/emarpiee/obsidian-rcrypt`
4. **プラグインを追加**をクリックし、コミュニティプラグインリストで **RCrypt** を有効化します。

### オプション 3: 手動インストール
1. 最新の [GitHub Release](https://github.com/emarpiee/obsidian-rcrypt/releases) から `main.js`、`manifest.json`、`styles.css`（利用可能な場合）をダウンロードします。
2. ディレクトリ `<vault>/.obsidian/plugins/obsidian-rcrypt/` を作成します。
3. ダウンロードしたファイルを `<vault>/.obsidian/plugins/obsidian-rcrypt/` に移動します。
4. Obsidian を再読み込みし、**設定** $\rightarrow$ **コミュニティプラグイン**で **RCrypt** を有効化します。

### オプション 4: ソースからビルド
```bash
cd /path/to/vault/.obsidian/plugins/
git clone https://github.com/emarpiee/obsidian-rcrypt.git
cd obsidian-rcrypt
npm install
npm run build
```

## 使用ガイド

### 1. プロファイル設定
1. **Obsidian 設定** $\rightarrow$ **RCrypt** を開きます。
2. **Crypt プロファイル**を作成または選択します。
3. **パスフレーズ**と**ソルト**を設定します（`rclone.conf` の `password` と `password2` に対応）。
4. **ファイル名暗号化モード**（`標準`、`難読化`、または`オフ`）を選択します。
   - **標準**モードの場合：**ファイル名エンコーディング**（`Base32` *（デフォルト）*、`Base64`、または `Base32768`）も選択します。
   - **オフ**モードの場合：**暗号化ファイルのサフィックス**（デフォルト：`.bin`、Rclone の `--crypt-suffix` デフォルトに合わせる）を設定します。

### 2. 基本的な暗号化と復号
- **コンテキストメニュー**：Obsidian ファイルエクスプローラーで任意のファイル、ファイル選択、またはフォルダを右クリックし、**暗号化**または**復号**を選択します。
- **コマンドパレット**：`Ctrl/Cmd + P` を押して **RCrypt** コマンドを検索し、アクティブなファイルまたは特定のパスを処理します。

### 3. ネスト（多層）暗号化ワークフロー
- **外側のレイヤーを追加**：すでに暗号化されたファイルまたはフォルダを右クリックして**暗号化**を選択します。外側のプロファイルを選択するかカスタム認証情報を入力します。
- **外側のレイヤーを解除**：多層ファイルを右クリックし、外側のプロファイルの認証情報を使用して**復号**を選択します。
- **内側のレイヤーの検出**：外側のレイヤーを復号すると、`obsidian-rcrypt` が出力バイトを検査して警告します：
  > 🔓 *外側のレイヤーを復号しました（1 件）。内側の暗号化レイヤーが検出されました！*
- **内側のレイヤーを解除**：残りのファイルを右クリックし、内側のプロファイルの認証情報を使用して**復号**を選択し、プレーンテキストを復元します。

> [!TIP]
> **多層暗号化のユースケース**：
> - **段階的アクセス制御**：機密ノートにプライベートな内側のパスフレーズを適用し、バックアップや追加保護のためにセカンダリの外側プロファイルでラップします。
> - **メタデータ難読化**：`オフ`または`難読化`モードで暗号化したファイルを外側の`標準`プロファイルでラップして、ディレクトリ構造と拡張子を難読化します。

> [!CAUTION]
> パス間で、テキストエディターで生のバイナリ暗号文ファイルを開いたり変更したりしないでください。テキスト変換によりバイナリヘッダー構造（`RCLONE\x00\x00`）が破損します。

## 暗号学的アーキテクチャ

| プリミティブ / コンポーネント | 実装 | 技術標準・パラメータ |
| :--- | :--- | :--- |
| **鍵導出** | `scrypt` | 80 バイトの鍵バッファを導出します（`N=16384`、`r=8`、`p=1`）。`dataKey`（バイト 0–31）、`nameKey`（バイト 32–63）、`nameTweak`（バイト 64–79）に分割。空の場合は Rclone の固定 16 バイトデフォルトソルトを使用。 |
| **ペイロード暗号** | `NaCl SecretBox` | XSalsa20 ストリーム暗号と Poly1305 MAC タグ（64 KiB ブロックあたり 16 バイト）。8 バイトのマジックヘッダー（`RCLONE\x00\x00`）と 24 バイトのベース nonce がプレフィックスとして付きます。 |
| **ファイル名暗号化** | `EME (AES-256)` / `難読化` / `オフ` | **標準**：`nameKey` と `nameTweak` を使用した PKCS#7 パディング付き AES-256 EME 広ブロック暗号（`Base32`、`Base64`、または `Base32768`）。**難読化**：Rclone 文字ローテーション暗号。**オフ**：オプションの拡張子サフィックス付きのプレーンテキスト。 |
| **多層暗号化** | `マルチパス XSalsa20` | Rclone CLI に一致する再帰的バイトレベルのペイロードラッピング。スマートバイト検査により復号後の内部 `RCLONE\x00\x00` ヘッダーを検出します。 |
| **ディスク上の認証情報ストア** | `AES-256-CTR Obscure` | Rclone の内部固定 256 ビット鍵とランダムな 16 バイト IV（Base64 URL セーフ）を使用した AES-256 CTR モード。 |

## セキュリティモデルと免責事項

### RAM 専用セッションストレージ（推奨）
- **ゼロディスクフットプリント**：**パスワードをディスクに保存**が無効の場合、パスフレーズとソルトは揮発性メモリ（RAM）にのみ保持されます。
- **自動パージ**：Obsidian を閉じたり、再起動したり、プラグインをアンロードすると、RAM 内の認証情報は自動的に削除されます。
- **手動パージ**：コマンドパレット（`Ctrl/Cmd + P`）から**セッションのパスワードとソルトをメモリから消去**を実行すると、認証情報が即座に削除されます。

### ディスク上の難読化ストレージ（`data.json`）
- **パスワードをディスクに保存**を有効にすると、Rclone の `rclone obscure` アルゴリズムを使用して認証情報が暗号化されます。
- *セキュリティ上の注意*：難読化されたパスワードは偶発的な閲覧から保護されますが、`data.json` へのローカルディスクアクセスとオープンソースの Rclone 鍵があれば誰でも復元できます。最高のセキュリティのために RAM 専用モードを使用してください。

> [!WARNING]
> **重要な警告と責任の制限**：
> - **回復不能なデータ損失**：暗号化はディスクファイルを直接操作します。認証情報が失われたり誤って設定された場合、誰もデータを復元できません。重要なノートの暗号化されていないバックアップを必ず保持してください。
> - **多層復号の順序**：ネストされたファイルの復号は、正確な逆順（外側 $\rightarrow$ 内側）で行う必要があります。中間レイヤーの認証情報を失うと、すべての内部コンテンツが永久にロックされます。
> - **サードパーティの Vault 同期**：同期ソリューション（Obsidian Sync、Git、iCloud）がプレーンテキストのソースファイルを同期しているのか、暗号化された出力を同期しているのかを確認してください。
> - **無保証**：MIT ライセンスの下でいかなる種類の保証もなく「現状のまま」提供されます。開発者は使用による データ損失または破損に対して一切の責任を負いません。
